## Vendored Nebula v1.11.2

- `reloadFirewall`, interface.go:462-510: `NewFirewallFromConfig` l.478, logs
  and returns on error l.480-482, `f.firewall = fw` l.502 (plain pointer, field
  l.62). Registered l.440-449.
- Readers of `f.firewall`: inside.go:75, 91, 107, 228; outside.go:521;
  interface.go:471, 484, 589.
- `NewFirewallFromConfig` (firewall.go:195) needs a `*CertState` (pki.go:33),
  whose constructors are unexported and which `Control` does not expose: package
  client cannot call it without a patch. Without one: exported
  `nebula.NewFirewall` (firewall.go:136) + `nebula.AddFirewallRulesFromConfig`
  (firewall.go:319), as internal/client/firewall_golden_test.go:205 does.
- `ReloadConfigString` (config/config.go:175-195) replaces `c.Settings`, runs
  every callback (PKI too, pki.go:59, re-reading the certs), and returns nil
  when the firewall is rejected. After a rejection `c.Settings` holds the
  rejected text, so the current rules must be read from the file.
- patches/README.md: one theme per patch, **no file in two patches**. An
  `atomic.Pointer` for `f.firewall` touches interface.go (owned by
  `read-loop.patch`) and outside.go (`paths.patch`): the plan has to settle that.
