# Problems
- (high) Write-then-reload ordering can leave a bad policy on disk. The design validates, writes nebula.yaml, then calls ReloadConfigString. A rejection at reload (firewall rule errors at firewall.go:386-408, or LoadString errors) leaves the bad file in place. The fallback reloadNebula then reads that same file (renew.go:1240-1243) and fails to start, so the mesh stays down until a fixed policy arrives.
  FIX: Validate the candidate against Nebula's own parser first: load it into a scratch config.C and build the firewall rules, without touching the live file. Only then write to a temp file, reload, and rename into place after success. Keep nebula.yaml.last-good for the fallback so a failed apply can restore it.
- (high) Data race on the firewall pointer in vendored Nebula. Interface.firewall is a plain *Firewall (vendor interface.go:62), written by reloadFirewall (interface.go:502) and read without synchronisation on the packet path (outside.go:521; inside.go:75, 228). Conntrack and rulesVersion reads are unsynchronised too. The design's core claim (tunnels stay up through an in-place reload) rests on this path, and make test-race with traffic will flag it.
  FIX: Add a vendor patch that publishes the firewall via atomic.Pointer (or an RWMutex) with a race test that reloads during live traffic. Record it in patches/README.md, apply with make patch-vendor, and run make test-race. Keep the netlab run before ship.
- (high) Four writers of nebula.yaml with no shared lock. routes.go:145-174 does an unlocked read-modify-write with os.WriteFile (not atomic) from the heartbeat goroutine. applyNebulaConfigUpdate (renew.go:798-812) holds only certInstallMu. ensureP2PConfig (renew.go:1131-1139) runs at boot. The design adds a fifth. Concurrent writes can lose updates, and a crash mid-write can truncate the file (an empty nebula.yaml already caused a boot panic, per the project CLAUDE.md).
  FIX: Introduce one per-instance nebula.yaml mutex and one helper (read, mutate, atomicWrite) used by all writers: firewall, routes, applyNebulaConfigUpdate and ensureP2PConfig. Switch routes.go to atomicWrite.
- (medium) Routes is not an in-place reload precedent. applyRoutesUpdate writes the file and calls reloadNebula (routes.go:54-63), which closes Nebula and restarts it, so a route change cuts tunnels today. The design's 'same pattern as routes' is true only for the heartbeat field (renew.go:491-496).
  FIX: State that the in-place reload is new code with new tests, and that reloadNebula remains the fallback. Do not cite routes as proof that config changes apply without dropping tunnels.
- (medium) Renewal wait is misstated. The design says a group change waits about 10 to 14 h. Renewals come 9.6 to 14.4 h apart (renew.go:631-637), so a change waits from 0 up to about 14.4 h. The design's rationale for rejecting groups should use that range.
  FIX: Correct the figure to 'up to about 14.4 h (renewal at 12 h +/- 2.4 h after issue)'. If group-based policy ever needs faster effect, trigger an immediate renewal on policy change, as roadmap item 8 already suggests.
- (medium) Golden test 'first heartbeat triggers no reload' compares text, but the default block changed in history (git log -G 'groups:' on the enroll files lists 41ce077, 791ac0b, 80fdbaa). Enrollments written by older agents may not match today's text, so the first heartbeat would reload for them, and 'migration writes nothing' would not hold.
  FIX: Compare the parsed rule set (rendered rules against parsed on-disk rules), not the text. Add golden fixtures from each historical template. Decide and state whether a one-time rewrite on the first heartbeat is acceptable.
- (medium) Existing DNS authz mismatch should be fixed first. The Add DNS button is shown to role-admin members (+page.svelte:87, 1204-1206), but CreateDNSRecord and DeleteDNSRecord require the owner (dns.go:106, 170). The design's 'UI gate and API gate must match' invariant is already broken here.
  FIX: Switch Create and Delete to CheckAccess(...).CanAdmin() to match the UI, add rows to TestE2E_DNS and TestE2E_Access, and remove the gap. Land this before the firewall work.
- (medium) node:<id> to nebula_ip mapping is not available to the agent as designed. The agent learns node IDs only through peerInfo keyed by overlay IP (renew.go:323-326; server renew.go:461), and only for peers the heartbeat lists.
  FIX: Have the server resolve node IDs to nebula_ip and send resolved CIDRs (agent validates them). Do not require the agent to derive the mapping from peerInfo.
- (medium) Reload E2E cannot be written against internal/e2etest as it is. StartPeer keeps only the service (peer.go:61), fixes the firewall to any/any (peer.go:42-44), and exposes no config or controller handle.
  FIX: Extend the harness to keep the *config.C and controller, expose a reload helper, and add a traffic helper, so the design's reload tests (A to B TCP allowed, rule removed, ICMP tunnel stays up) can run under -race.
- (medium) The /proxy claim understates the firewall. The dashboard's /proxy is authorised by capabilities, but it reaches port 41820 only through the admin-group rule the firewall renders (enroll.go:661-665; Drop at outside.go:521). A policy that drops admin->41820 breaks /proxy and port forwards.
  FIX: Say that capabilities authorise /proxy and the firewall must keep admin->41820 (invariant 1). Add a test row to TestE2E_Proxy that applies a restrictive policy and confirms /proxy still works.
- (low) Audit is not a shared facility. h.audit is a ProxyHandler method (proxy.go:31), and capability and route writes are not audited (proxy.go:1120-1165, 1181 onward). A firewall handler cannot simply call h.audit.
  FIX: Extract the audit helper into a shared function usable by any handler, and add audit calls to capability and route writes in the same change, as the design requires.
- (low) Clipboard precedent is cited with the wrong path and implies a live apply it does not have. The file is clients/desktop/src/lib/Settings.svelte, and the handler returns restartRequired: true (local_api.go:1442).
  FIX: Cite clients/desktop/src/lib/Settings.svelte. Do not present the clipboard switch as a live-apply precedent; the shield's immediate effect depends on the new reload path.
- (low) Netlab justification is wrong. reloadFirewall does not touch the hostmap (interface.go:462-510), and the netlab rule 1 trigger in the project CLAUDE.md covers paths, hostmap/handshake/connection-manager patches and keepalives.
  FIX: Give the real reason (the reload is on the live data path) and run netlab before ship. Do not cite rule 1 as triggered.
- (low) Rendered block does not pin the drop action. Nebula's default inbound and outbound action is drop, but a reject setting (firewall.go:216-236) would send resets or ICMP to denied peers.
  FIX: Render firewall.inbound_action: drop and firewall.outbound_action: drop explicitly, and have the validator reject any other value.
- (low) A partial config would drop settings. ReloadConfigString calls LoadString, which replaces the whole settings map (config.go:381, 409). Passing only the firewall fragment would silently clear every other setting.
  FIX: Always pass the complete, validated nebula.yaml text to ReloadConfigString.
- (low) The kernel-TUN root test the design cites as a gate could not be located. Only internal/client/migrate_chown_test.go references the privilege check.
  FIX: Find and name the exact kernel-TUN test before writing it into the gate list, or add it.
