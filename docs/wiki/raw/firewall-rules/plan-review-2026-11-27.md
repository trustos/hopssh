## Skeptical review of the default and of sharing

- **Item 3: wrong.** Read-only review; nothing was run. (a) Trust delta. The agent block already allows TCP any from node (enroll.go:666-670), so on a kernel-TUN install every member already reaches every TCP listener on every device. UDP adds UDP-only or UDP-first listeners that answer unauthenticated requests. Examples to test, not verified on these OSes: mDNS 5353 (macOS; Linux with Avahi), SSDP 1900, WS-Discovery 3702, LLMNR 5355 and NetBIOS 137/138 (Windows), rpcbind 111 and NFS over UDP (Linux, if enabled), syslog 514 (if a receiver is set up), Syncthing discovery 21027 and QUIC 22000, Jellyfin discovery 7359, WireGuard, mosh while a session is open, QUIC on 443. Multicast is not carried (renew.go:1051 drop_local_broadcast), but unicast to these ports arrives. So the UDP widening is modest. The bigger point is that TCP-any already lets any member reach any device, and the draft leaves that unexamined although its own concept says shared networks are where the risk is. (b) Clients. cli_join.go:203-214 sets tun user true, and cli_join.go:137 starts Nebula with no listener and no keepalive, so the ICMP-only block protects no service. It does cost something. keepaliveOneCycle (keepalive.go:338-385) probes every non-lighthouse peer on 41820 with no client filter, because pathQualityRecent always returns false (keepalive.go:399-401). A DROP times out, and only a refusal counts as alive (keepalive.go:126). So an agent whose only other direct peer is a client should count each cycle as stuck while the client stays in the hostmap. Read from code, not reproduced. The exception also contradicts the user's 'allow everything', and the draft gives no reason for it. (c) Heal. ensureP2PConfig writes only when a managed key changed (renew.go:1127-1136), so on-disk text is either the template or yaml.v3 output, and a byte match works only on files that were never rewritten. It already overwrites fixed keys (timers renew.go:986-996, listen buffers 963-968, punchy delay, tun dev). The firewall section is not among them, so hand-edited firewall blocks survive today, and the heal keeps that for any block that does not match. The real risk is classification: an admin's deliberate default cannot be told from an unedited one, and the heal turns it into allow-all. The heal also contradicts the wiki's own decision that existing networks keep what they have (concept, Decide). The draft's 'all networks, old and new' ignores that agents update only when someone runs hop-agent update (CLAUDE.md), so a network stays mixed for a long time. The claim 'new networks only is not possible before P2' is false: the enrollment writer (enroll.go:655) already varies per enrollment, so a per-network default carried in the enroll answer gives new-network-only without P2's reload machinery.
  - Correction: Ship only the new-enrollment default, read from a network attribute returned in the enroll answer, with existing networks untouched (no P2 needed). Do not heal existing agents without the owner's explicit yes, and then only behind a kill switch and a classifier test. Allow TCP 41820 from node on clients, or exclude clients from the keepalive and path probes, and verify in netlab. Consider a narrower UDP rule on named ports instead of any-UDP.
- **Item 4: partly.** Roadmap #8 (docs/roadmap.md:102) asks for rules reusable 'across multiple networks in the same account', keyed 'to the account/team, not the network, with per-network opt-in'. The schema has no account or team table: 001_initial.sql:104 calls network membership 'teams', and networks carry user_id. So 'owned by the account' in the draft means one user's library, which goes with that user. Settle this before P1. The draft says 'none of the five products read has' an override; the research only says none documents one. Surprises the draft does not cover: (1) Node references. nodes.id is a TEXT key (001_initial.sql:41-45) and no migration makes hostname unique, so a rule naming a node by hostname matches every device of that name in the target network. A node of another network matches nothing, silently. Bind rules to network-scoped node IDs, resolve them on each heartbeat, never store addresses (migration 008 reuses addresses after 48 h), and refuse dangling references at attach time. (2) Authority. An attached allow-all set cannot be narrowed by a network's role-admin, and the draft does not say who may attach, detach or edit. An edit changes every attached network at once. (3) Detach. A removed rule kills open flows at their next packet, and they do not come back (verification-2026-11-27.md, spike 2b). Detaching is therefore a removal and needs the same warning. (4) Device switch. P3's 'block incoming' is a deny that wins over the union, which is an override, so 'no override' has to say so.
  - Correction: Keep the union of allows, but add: network-scoped node IDs, refusal of dangling references, an explicit authority model, a detach warning, and wording that the P3 deny is an override. Change 'none of the five products read has' to 'none of the five documents'.
- **Item 5: partly.** (e) P0 as written is not the prerequisite for healing. The heal needs a classifier that recognises the historical blocks by parsed comparison, and P0's golden tests are exactly that test set, so keep them. The 'one renderer for agent and client blocks' refactor is not needed for the heal. The real prerequisite is item 9. The heal adds a boot-time write to nebula.yaml, and the routes writer does an unlocked read (routes.go:147) followed by a truncating write (routes.go:173; verification-2026-11-27.md claim 3). A heal written between those two steps is reverted, and a truncated file leaves the mesh with no usable config. Item 9 (shared lock, atomicWrite) must therefore land first. The draft also gives no red test for the heal itself.
  - Correction: Order: item 9 first, then the classifier with P0's golden tests, then the heal behind a kill switch. Drop the renderer refactor from the heal's prerequisites.
