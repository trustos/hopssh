# Verdicts
- [confirmed] Today's agent firewall is: outbound any; inbound TCP agent API port from admin; inbound TCP any from node; inbound ICMP from any host. It is written at enrollment and not reloaded.
  -> internal/client/enroll.go:655-674 contains exactly these blocks. writeNebulaConfig runs at enrollment (enroll.go:480, 557; local_api.go:1191). Later rewrites (ensureP2PConfig renew.go:911, applyNebulaConfigUpdate renew.go:774) round-trip the file through a YAML map, so the firewall block survives them.
- [confirmed] Agent node certs are issued with group node and name node-<8 chars> (renew.go:137-138; enroll.go:179-180).
  -> renew.go:136-138, enroll.go:180, enroll.go:312, bundles.go:80 and device.go:191 all issue []string{node}. The device-flow path (device.go:191) also gives owner devices group node, so owner and member devices cannot be told apart by group.
- [confirmed] The server's own cert is issued with groups admin and node (networks.go:101).
  -> internal/api/networks.go:101 passes []string{admin, node} to pki.IssueCert.
- [confirmed] The heartbeat response adds optional fields only when present, following the routes pattern (renew.go:491-496).
  -> renew.go routes block adds resp[routes] only when len(routes) > 0, with a comment saying an empty list omits the field.
- [confirmed] The heartbeat body is capped at 1 MiB, and no DisallowUnknownFields in internal/api means old agents ignore new response fields.
  -> renew.go:198 uses http.MaxBytesReader(w, r.Body, 1<<20). A grep of internal, cmd and clients finds no DisallowUnknownFields anywhere, so the agent's decoder is also lenient. The design cites only the server side, but the conclusion holds for the whole tree.
- [confirmed] The agent keeps no *config.C after start; the Nebula config is a local variable (nebula.go:67, 129).
  -> internal/client/nebula.go:67 and :129 declare var cfg config.C, used only inside the start function and passed to nebula.Main (:77, :139). Nothing else retains it, so the design's point that an in-place reload needs a retained pointer is correct.
- [confirmed] ReloadConfigString re-parses the text, holds the reload lock and runs all registered callbacks (config.go:175-190).
  -> vendor/github.com/slackhq/nebula/config/config.go:175-190 takes reloadLock, calls LoadString(raw), then runs every callback in c.callbacks. Every callback, not just the firewall one, runs on each reload, which matters for unrelated pending changes (problem 6).
- [confirmed] reloadFirewall rebuilds the firewall only when the firewall key or the certificate's unsafe networks changed (interface.go:441, 462-470).
  -> vendor/github.com/slackhq/nebula/interface.go reloadFirewall returns early unless c.HasChanged(firewall) or certUnsafeChanged.
- [confirmed] reloadFirewall keeps conntrack, so an established flow is re-matched on its next packet and a removed rule cuts that flow.
  -> interface.go reloadFirewall sets fw.Conntrack to the old table. vendor firewall.go:528-551 (inConns) re-checks each old entry against the new rule table on its next packet and deletes it when no rule matches, and keeps it when one does. Only flows whose rule was removed are cut. The design's wording matches the code.
- [confirmed] nodes.nebula_ip is a TEXT column that can back a per-node /32 source rule (001_initial.sql:41-61).
  -> internal/db/migrations/001_initial.sql:49 nebula_ip TEXT, nullable. A unique index on (network_id, nebula_ip) exists at line 132. The column exists, but it is not a stable identity over time (see problem 5).
- [confirmed] CanView is true for any role, CanAdmin is role admin, and the owner is handled in the access check rather than in CanAdmin (authz.go:31, 34).
  -> internal/authz/authz.go: CanAdmin returns Role == admin. CheckAccess returns admin for the network owner. So a PUT gated on CanAdmin of a raw membership row would lock out the owner; the gate must be CheckAccess(...).CanAdmin().
- [confirmed] The DNS add mismatch is the warning the design raises: the UI and API gates must match.
  -> internal/api/dns.go:59-60 lists with CheckAccess and CanView, but create (dns.go:106) and delete (dns.go:170) use owner-only CanAccessNetwork. The API mismatch is real. Frontend gating was not checked.
- [confirmed] Roadmap item 8 (granular firewall rules with tags, compiled to cert groups plus firewall config) is the existing plan this design extends.
  -> docs/roadmap.md:102 exists with that description. The same row also says tags, roles and rules are account-scoped with per-network opt-in, which the design's one-policy-per-network row contradicts (problem 11).
- [confirmed] hop client join has no heartbeat, so clients get no policy and keep ICMP-only inbound (cli_join.go:206-215).
  -> internal/client/cli_join.go has no heartbeat code. The firewall block at lines 206-215 allows inbound ICMP only and sets tun user true. The client path also has no 41820 reference.
- [confirmed] Heartbeat latency is about 60 s.
  -> internal/client/api.go:102-103 defaults HeartbeatInterval to 60 s, and no caller overrides it. CLAUDE.md's 30 s figure is stale.
- [unclear] Clipboard-sync precedent path: Settings.svelte:627-640 -> local-api.ts -> POST /local/clipboard-sync (local_api.go:131) -> Enrollment.ClipboardSync (enrollments.go:49).
  -> The route (internal/client/local_api.go:131) and the field (internal/client/enrollments.go:49, ClipboardSync) exist. The cited clients/desktop/src/Settings.svelte does not exist at that path, so the UI half of the citation could not be checked.
- [unclear] Kernel TUN gates host services such as sshd and Screen Sharing; userspace gates only netstack listeners (section 6).
  -> The Nebula firewall drops inbound packets before any write to the TUN or netstack in both modes (vendor outside.go:521 Drop, then f.readers[q].Write). The mode decides what is reachable, not what is gated. With the default TCP-any-from-node rule, every kernel-TUN host's TCP ports are reachable from every node device. The sentence as written hides that.
- [wrong] Invariant 1 rationale: shell, exec, proxy and path probes depend on TCP 41820 from admin.
  -> Shell, exec and proxy come from the control plane (admin): proxy.go:580, 944, 1409 dial nodeIP:41820. But the agent's own keepalive dials each peer's 41820 from its node certificate (internal/client/keepalive.go:379, dial at :111-119), so those are node-source probes that the admin-only invariant does not cover. Path probes in path_watch.go do not dial 41820 at all.
- [wrong] A per-node source is as strong as the cert, because the overlay IP is bound by the peer's cert.
  -> internal/db/nodes.go:409-430 (NextNodeIndex) takes the max over live nodes, so deleting the highest-index node frees its IP for the next enrollment. The deleted node's cert stays valid until NotAfter and Nebula does not query the database, so two valid certs can hold the same IP, and a cidr /32 rule matches both.

# Problems
- (high) The default rule (TCP any from node) lets every device in a network reach every TCP port on every kernel-TUN node, including sshd and Screen Sharing, and the design keeps that default silently. enroll.go:655-674 sets it; outside.go:521 drops before the TUN write, so the firewall applies in kernel mode too. Migration writes nothing, so the owner is never shown this exposure, and the new tab would look configured while showing nothing.
  FIX: Show the default as explicit, editable rows, with a per-node banner such as 'every device in this network can reach all TCP ports on this node'. Offer a preset that narrows it to admin plus ICMP. Rewrite section 6 so it says the firewall applies in both modes and the mode only decides what is reachable. Never show an empty tab as if it were a safe policy.
- (high) A common restrictive rule, such as allow TCP 22 from node only, drops TCP 41820 between nodes. Every keepalive probe then fails (keepalive.go:379), the watchdog trips after three stuck cycles of 90 s (keepalive.go:169-173, about 4.5 min), and the instance restarts. The restart backoff only caps the rate, and each restart drops working tunnels. recovery.go:304 already names this exact case as a stuck data plane.
  FIX: Add TCP 41820 from node to the always-on invariants. The default already allows it, so existing networks do not change. Add a test: a deny-all policy still renders that rule, and the keepalive stays green with the policy applied. Correct the invariant 1 rationale, because peer probes come from node, not admin.
- (high) A bad policy can take the whole mesh down. The design writes the file, reloads, and on reload error calls reloadNebula (close and start). reloadNebula closes the old Nebula first (renew.go, v0.10.33), so a bad file leaves no Nebula running. The next start on connect or boot then falls back to the OS stack (client.go:266, 285), and the bad file stays on disk. This also contradicts the design's own 'keep the last applied rules'.
  FIX: Render to a temp file, run ReloadConfigString first, and rename over nebula.yaml only on success. On failure keep the running config and the old file, and report firewallError in the next heartbeat. Never close and start with an unvalidated config. Test: a rejected policy leaves tunnels up and the file byte-identical.
- (high) The OS-stack fallback listens on :41820 on every interface, outside the Nebula firewall. serverset.go:75 calls net.Listen(tcp, :41820). client.go:266 and 285 use it when nebula.yaml is missing or every Nebula mode fails, which is a real state (the v0.11.23 notes record a port-bind failure there). cmd/agent/main.go:227-228 wraps the whole mux in bearer middleware (main.go:250-254), which is the only gate on /exec, /shell and /upload. The design treats 41820 as reachable only through Nebula, so its invariants and threat model are wrong for that state.
  FIX: Bind the fallback listener to 127.0.0.1, or do not serve the mesh mux in fallback at all. State the reachability boundary in the design. Add a test that the fallback never listens on a non-loopback address.
- (medium) Node IPs are reused after deletes, so a rule keyed on IP can change meaning. NextNodeIndex (db/nodes.go:409-430) takes the max over live nodes, so deleting the highest-index node frees its IP for the next enrollment (enroll.go:72). The old cert stays valid until NotAfter, and Nebula checks no database, so a cidr /32 rule matches both holders.
  FIX: Allocate indexes from a per-network counter that never reuses a value (one column on the networks table). Key per-node sources on node identity or cert fingerprint, not IP. On node delete, add the cert fingerprint to pki.blocklist (see problem 8).
- (medium) A whole-file reload applies unrelated pending changes. applyNebulaConfigUpdate (renew.go:774-820) writes server-pushed relay, punch and MTU settings to disk with atomicWrite and never reloads the running Nebula. renew.go:756 only logs errors. A firewall edit that writes the whole file and calls ReloadConfigString would apply those pending changes in the same reload, and the design does not account for that.
  FIX: Before a firewall reload, diff the disk file against the loaded settings. If they differ, either reload deliberately with a test, or mark the firewall change pending until restart. Better: build the new text from in-memory settings with only the firewall key replaced.
- (medium) Rules that point at deleted or foreign nodes are unspecified. Node sources are resolved from nodes.nebula_ip at render time, so a deleted node has no address, and the design does not say whether the rule is dropped, errors, or fails open. The PUT also does not say that node IDs are checked against the network.
  FIX: Specify fail-closed: drop the rule, show a warning on the tab, and never widen access. Validate every node ID against the network on PUT. Add tests for deleted-node and foreign-node references.
- (medium) There is no way to isolate one device. With an allow-only model and an any-node default, cutting off one device means rewriting the default. Deleting a node does not revoke its cert, which stays valid until NotAfter. Nebula's pki.blocklist (vendor pki.go:562) is the revocation primitive, and reloadCAPool runs on each config reload (pki.go:86), but whether a blocklist change takes effect on reload was not traced end to end.
  FIX: Add isolate-device as a first-class action: blocklist the device's cert fingerprint on peers and remove its allows. Confirm with a test that a blocklist change applies on reload before relying on it. Until then, say in the UI how long a removed device keeps access.
- (medium) The owner gate is easy to get wrong. CanAdmin checks only the role (authz.go), and the owner is admin only through CheckAccess. The DNS code already shows the mismatch: list uses CheckAccess (dns.go:59-60), while create and delete use owner-only CanAccessNetwork (dns.go:106, 170).
  FIX: Gate the firewall PUT on CheckAccess(user, network, membership).CanAdmin(). Add TestE2E_Access rows for owner, admin member, member, outsider and anonymous. Do not copy the DNS create pattern.
- (medium) Most nodes will show 'agent too old', and that state hides that the policy is not enforced there. Agents do not update themselves (CLAUDE.md deployment note), and old agents keep the default block and ignore the new field, so the default exposure from problem 1 stays in force on those nodes.
  FIX: Label these nodes 'not enforced: agent too old, still open as before', not 'pending'. Show 'applied' only after an acknowledgement from the agent.
- (medium) Roadmap item 8 conflicts with the storage model. docs/roadmap.md:102 says rules and tags are account-scoped with per-network opt-in. The design makes one policy row per network and says tags will come 'on the same policy object', so tags later would need a migration.
  FIX: Decide before phase P1. Either supersede item 8 in docs/roadmap.md and write down the migration from per-network to account-scoped rules, or make the row account-scoped now with a link to the network.
- (medium) Client devices sit outside the UI and can trip the watchdog. Clients get no policy and only ICMP inbound (cli_join.go:206-215). The keepalive skips only lighthouses (keepalive.go:340-352), so a client in an agent's hostmap is probed on 41820, which the client path does not serve (cli_join.go has no 41820 reference). Not verified at runtime.
  FIX: Label clients 'not governed' in the target list and in the who-can-reach view. Exclude clients from keepalive probes, using node type from the heartbeat or cert group, and add a test with a client-only peer.
- (medium) The editor asks a novice for proto, port, source and target, but the request is 'let my devices talk UDP'. Nothing maps plain outcomes to rules. The answer to the question is yes, the UI is the right place, but it needs a plain-language layer before the rule table.
  FIX: Offer a top-level choice: 'devices talk freely', 'only ping and admin', or 'custom rules'. Presets compile to the same rule JSON, and the table sits behind 'custom'. Name protocols and ports in plain words, for example 'for games or voice apps, allow UDP ports ...'.
- (low) The apply path compares text, but ensureP2PConfig rewrites the YAML through a map (renew.go:911-935, parseNebulaYAML), so the file text no longer matches what writeNebulaConfig produced. A text comparison would reload on every boot.
  FIX: Compare the parsed firewall structure, not the text. The golden test should check that a default-equal policy causes no reload.
- (low) The control-plane source is redundant. Dashboard traffic reaches nodes over 41820 (proxy.go:580, 944, 1409), and invariants 1 and 2 already allow admin. No port needs an admin-source rule.
  FIX: Drop control-plane from the MVP source set.
- (low) The MVP carries speculative scope: a history table (the audit log already records old and new versions via h.audit, and revert can copy from there), preview counts, and the device shield.
  FIX: Ship P0 to P2 plus the editor and presets. Add the history table, preview and shield when a user asks for them.
- (low) Edits reach nodes only on the next heartbeat (api.go:102-103 defaults to 60 s), so a compromised device stays reachable for up to a minute after an edit.
  FIX: State 'up to 60 s' in the editor. Accept this for the MVP, and document it for the isolate action in problem 8.
