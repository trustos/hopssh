# Audit log coverage, 2026-11-27

What the control plane writes to `audit_log` for each route that changes
something. "Before" is the tree at commit 9b7964b; "after" is the change that
added `TestE2E_Audit` (`internal/api/audit_e2e_test.go`), which holds the
authoritative lists (`auditedRoutes`, `notAudited`, `readOnly`) and fails when
a route is in none of them or in more than one.

Read with `GET /api/audit` (the caller's own entries) or
`GET /api/networks/{id}/audit` (a network's). Details are JSON; they never hold
a token, a code or a key.

but the GitHub callback (the tests have no GitHub).

The three deletes (`member.remove`, `invite.revoke`, `dns.delete`) write an
entry only when they deleted something: an ID that is not there, or the
second of two deletes at once, answers 204 as before and writes nothing. The
stores report it (`:execrows`, `(bool, error)`); before, a member removal or
an invite revoke of nothing wrote an entry, and of 16 DNS deletes at once
several did.

## Who a machine's entry names

`POST /api/enroll`, `GET /api/bundles/{token}` and `POST /api/device/poll` are
called by a machine without a session. Their entry names the user who made
the credential: the creator of the enrollment token or bundle, or the user who
approved the device code. Migration 010 adds `nodes.created_by`, written in the
same transaction as the node by every path that creates one
(`NodeStore.Create`: `CreateNode`, `JoinNetwork`, `CreateBundle`, device
`Poll`). A token or bundle made before the migration has no creator and its
redemption writes no entry; both live at most 15 minutes. Nodes created before
the migration keep NULL.

## Not audited, on purpose

| Route | Why |
|---|---|
| `POST /api/auth/logout` | ends the caller's own session |
| `POST /api/device/code` | anonymous; the code does nothing until a user approves it |
| `POST /api/renew` | machine traffic, a few times a day per node |
| `POST /api/heartbeat` | machine traffic, every 30 s per node |
| `POST /api/clipboard/announce` | machine traffic |
| `GET …/nodes/{nodeID}/health` | liveness only: an answer marks the node online, and a change of status goes to the network's events |

The GETs that change nothing are listed in `readOnly` (27 of them). A GET is
not taken on trust: a new one fails the test until it is put in one of the
three lists.

## What no entry may hold

The test collects every secret it is handed and fails if any entry holds one:
invite codes, enrollment tokens, the agent token of every way a node comes in
(`/api/enroll`, `/join`, `/api/device/poll`, the bundle), device codes and
user codes, and bundle tokens.

## Not covered, seen while doing this

- Work done by the server itself writes no audit entry: the status sweeper,
  a network's cascade on delete (its nodes, DNS records, invites), and the
  hourly prune that runs only when `HOPSSH_NODE_PRUNE_AGE_HOURS` is set
  (`internal/db/status_sweeper.go`; it writes a count to the server's log and
  nothing to `audit_log`). The network delete is logged once, for the network.
- A member who is removed keeps for a few minutes what they made before: an
  enrollment token (10 min), a bundle URL (15 min) or a device code they
  approved still brings a node into the network, and the entry names them.
  `Enroll`, `Poll` and `DownloadBundle` check no membership. Proposed, not
  done: refuse them when the creator is no longer in the network.
- Failed logins write no entry (only the rate limiter sees them).
- A network's audit log is readable by every member (`CanView`), so every
  member sees the address a machine enrolled or downloaded a bundle from.
  That address is `X-Forwarded-For` only with `--trusted-proxy`; whether it is
  the client's behind Traefik in production was not checked.
- Two deletes of the same network at once can both write `network.delete`:
  each reads the network before either deletes it, and `Networks.Delete` does
  not report whether it deleted anything. Owner only, so a nit.
- `members.go` still has a branch for `sql.ErrNoRows` from `Remove`, which no
  longer returns it.
